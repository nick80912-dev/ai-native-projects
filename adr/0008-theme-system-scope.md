# ADR 0008 — 主題系統交付範圍:六組淺色主題(Six-Theme Scope Ratification)

> 狀態:**Accepted**(2026-07-30 由 Bar 追認)。本 ADR 記錄一次**已完成交付超出原核准範圍**的事實與追認結果,不推翻 ADR 0002/0004 的任何既有決策,也不改變主題只能覆寫第一層 token 的既有約束。

**Decision**:主題系統的正式交付現況為 **6 組淺色主題**,`THEME_IDS=['ocean','ivory','wisteria','cedar','mist','tea']`,預設維持 **`ocean`(海洋／岡山)**。此範圍由 Bar 於 2026-07-30 **事後追認為正式交付現況**,不要求回退到原核准的選項數。**自本 ADR 起,新增或移除任何主題一律須先取得 Bar 核准,不得以「已有六個、多一個無妨」為由自行增補。**

**Context**:主題系統的核准範圍經過兩次演進,而實際交付超出兩者:

| 時點 | 核准範圍 | 出處 |
|---|---|---|
| 2026-07-17 | 保留現行海洋色為預設,**另新增兩個主題,共三選項** | `tasks/backlog.md` #6 原始版本 |
| 2026-07-30 | 鬆綁為三案並列評估(象牙／靛藍、藤紫／夜櫻、杉綠／宮島),**最終選項數(三或四)待 Bar 裁定** | `tasks/backlog.md` #6 修訂版(commit `04de67f`) |
| 2026-07-30(實作) | **6 組**:ocean、ivory、wisteria、cedar、**mist**、**tea** | `index.html` `THEME_REGISTRY`;SW v72 |

具體差異是:`ivory`／`wisteria`／`cedar` 三案在核准範圍內;**`mist`(霧藍／瀨戶,chrome `#3f4c5e`)與 `tea`(焙茶／倉敷,chrome `#4e3d32`)兩組未經任何核准即納入交付**,且交付時的選項數(6)超出「三或四」的待裁定區間。此為治理落差,非技術缺陷 — 六主題本身已通過完整自動化與 Browser QA 驗證(見 `07_CHANGELOG.md` 2026-07-30 條目)。

同批附帶修正 `--green` 由 `#3c8062` 改為 `#367055`:舊值在現行海洋紙上對比僅 4.18,低於 WCAG AA 4.5,屬**既有缺口非主題造成**;新值在四種底色皆 ≥5.17。此修正在 #6 原文中已明列,屬核准範圍內。

**Alternatives Considered**:
- **A. 回退到四組(砍掉 mist 與 tea)**:嚴格符合原核准範圍。但兩組主題已完整通過 13 個 `--t-*` token 補齊、對比測試、六主題 `data-theme`／meta／topbar／tabbar 的 Browser QA 驗證;砍掉是為治理形式付出真實的功能與測試回歸成本,且 v72 已推送 `dev`。
- **B. 靜默接受,不留紀錄**:最省事,但讓「範圍擴張無代價」成為慣例,牴觸 `15_AI_EXECUTION_RULES.md` §2「嚴禁以『應該是這個意思』自行擴大任務範圍」。
- **C. 只在 `tasks/done.md` 記一行差異,不開 ADR**:任務板是流動狀態,`done.md` 會隨旅程結束封存;主題數量是後續每次新增主題都要回頭對照的約束,需要永久紀錄。
- **D. 追認現況 + 開 ADR 立下未來閘門(採用)**。

**Why This Decision**:選 D 是因為「已交付且驗證通過的功能」與「未來的範圍紀律」是兩件可以分開處理的事。回退(A)拿真實的品質成本換形式合規,不划算;靜默(B)拿治理紀律換省事,代價更貴。追認 + 立閘門讓這次的擴張成為**一次性的、有紀錄的例外**,而非可複製的先例 — 這正是 `15_AI_EXECUTION_RULES.md` §1「覆寫僅限當次,不延續、不入慣例;若 Bar 希望永久放寬,改文件而非累積口頭例外」所指的「改文件」。ADR 而非 `done.md`,是因為約束的生命週期比任務板長。

**Expected Benefits**:六主題交付與其測試資產完整保留,無回歸風險。範圍擴張留下可追溯的書面紀錄(原核准 → 實際交付 → 追認),而非只存在於對話。未來任何 AI 接手要新增第七個主題時,會在 `adr/` 讀到明確的「須先核准」閘門,不會誤以為主題數量是自由的。

**Trade-offs**:
- 追認等於承認「先做後認」在本次可行,存在被引用為先例的風險 — 以本 ADR 的明文閘門與 `15_AI_EXECUTION_RULES.md` §4 禁改清單硬停規則對沖。
- 六個選項的設定頁主題格比三、四個更長,`320px` 寬度下需捲動;已於 Browser QA 驗證水平溢位 0。
- 每新增一個主題,13 個第一層 token 的對比測試成本線性增加。

**Future Impact**:
- 新增／移除主題:**先取得 Bar 核准**,再依 `04_UI_GUIDELINES.md` 補齊 13 個第一層 `--t-*` token 並通過自動對比測試;`THEME_IDS` 與 `THEME_REGISTRY` 須同批更新,未知主題一律回退 `ocean` 並記診斷(現行行為,不得移除)。
- 預設主題變更屬使用者可感知的行為變更,亦須 Bar 核准。
- 深色模式**不在**本 ADR 範圍(六組全為淺色系);若未來要做,屬新決策,需另立 ADR。
- 第二層語意角色(`--paper`／`--card`／`--sea-deep`／`--sea`／`--coral` 等)與四分頁結構的穩定性約束不受本 ADR 影響,見 `08_AI_HANDOVER.md` 與 `.ai-manifest.json` `invariants_never_break`。
