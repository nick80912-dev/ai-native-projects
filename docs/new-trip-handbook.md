# 換下一趟旅程：操作手冊（v150 起）

> 給旅程負責人（Bar）與旅伴。技術決定見 [ADR 0021](../adr/0021-connect-new-trip.md)。
> **前提**：v151（含 v150 的連接新旅程）已發布到正式站。岡山旅程期間的手機由「岡山保護期」照顧（見文末「發布時機」）。

## 一、建立範本（只做一次）

範本是之後每趟旅程複製的起點。

1. 打開岡山的試算表，「檔案 → 建立副本」，命名為「TripPilot 範本」。
2. 在副本裡：
   - **分帳紀錄**：只留第一列標題（21 欄），刪除所有資料列。
   - **行程總表、Places、Restaurants、Shopping、Hotels、Expenses**：保留標題列，資料列刪掉或留作範例。
   - **行程總表**：在「備註」右邊新增一欄，標題打 `行程ID`（選填，見第四節）。
   - **TripConfig**：在最下面新增三列：

     ```csv
     Trip ID,改成新的一組文字
     Ledger Endpoint,
     Weather Regions GID,
     ```

   - 新增一個分頁，命名「天氣地區」，第一列標題：`地區名稱,緯度,經度,關鍵字`。
3. 「擴充功能 → Apps Script」，把 GitHub 上最新的 `apps-script/ledger-sync.gs` 完整貼上並儲存。**這是範本的副本，不會影響岡山正在用的部署。**

## 二、每趟旅程（Bar）

1. 打開範本，「檔案 → 建立副本」，命名例如「2027-03 九州」。Apps Script 會跟著複製。
2. 填 **TripConfig**：

   | 鍵 | 怎麼填 |
   |---|---|
   | Trip Name | 顯示在 App 標題，例如 `九州五日` |
   | Start Date／End Date | `YYYY-MM-DD`，開始不能晚於結束 |
   | Travel Mode | `Driving` 或 `Transit` |
   | Currency | 當地幣別的三碼，例如日本 `JPY`、韓國 `KRW`、泰國 `THB`、美國 `USD`、歐元區 `EUR`；沒填就是 `JPY`（v168） |
   | Exchange Rate | 1 單位當地幣等於多少台幣，例如日圓 `0.21`、韓元 `0.024`、美元 `32.1`。**可以先不填**，之後在 App「設定 → 分帳設定」補填，存下後全團共用（v168） |
   | Ledger Default Currency | 全團結算幣別：這趟的當地幣別（例如 `KRW`）或 `TWD`；沒填就是當地幣別 |
   | Trip ID | **每趟都要不同**，3–40 個英文字母、數字、`-` 或 `_`，例如 `kyushu-2027-03` |
   | Ledger Endpoint | 第 4 步取得的網址 |
   | Weather Regions GID | 第 5 步取得的數字（不需要天氣可留空） |

3. 填行程總表、Places、餐廳、購物、住宿。
4. **部署 Apps Script**：「擴充功能 → Apps Script → 部署 → 新增部署作業」，類型選「網頁應用程式」，執行身分「我」，存取權與岡山的部署相同。部署後複製結尾是 `/exec` 的網址，貼到 TripConfig 的 `Ledger Endpoint`。
   - 檢查：在瀏覽器打開「那個網址 + `?action=info`」，應該看到 `{"ok":true,"tripId":"你填的 Trip ID","ledgerHeaderOk":true}`。
5. **天氣地區**（選填）：在「天氣地區」分頁每列填一個地區。
   - 緯度、經度：在 Google 地圖對地點按右鍵，第一行就是「緯度, 經度」。
   - 關鍵字：行程或地點名稱裡出現這些字，就用這個地區的天氣；用「、」分隔，例如 `天神、博多、中洲`。
   - 打開這個分頁時，網址最後 `gid=` 後面的數字，填到 TripConfig 的 `Weather Regions GID`。
   - 沒有這個分頁時，新旅程不會顯示天氣（不會再用岡山的城市猜）。
6. **發布到網路**：「檔案 → 共用 → 發布到網路」，選「整份文件」，按「發布」。複製產生的連結，開頭是 `https://docs.google.com/spreadsheets/d/e/`。
7. 把這個連結傳給旅伴。**不要傳「共用」的編輯連結**（`/d/` 後面直接接 ID、結尾 `/edit` 的那種）。

## 三、旅伴（每個人自己的手機）

1. 上一趟結束後：「設定 → 資料與版本 → 清除並打包旅程」。清除前全團的帳要結清；可以選擇先封存到自己的 Google Drive。
2. 首頁出現「目前沒有進行中的旅程」（新手機是「尚未連接旅程」），按 **連接新旅程**。
3. 貼上 Bar 傳來的連結，按 **檢查連結**。App 會下載整份試算表並檢查，約幾秒鐘。
4. 看預覽：旅程名稱、日期、每天幾個行程、已加入的成員。沒問題就按 **確認連接**，App 會重新開啟。
5. 到分帳頁選自己的名字（每趟旅程重新選）。

## 四、行程ID（選填）

- 行程總表的「行程ID」欄有填，就用它當作這一列的固定 ID；之後在中間插入或刪除列，打卡和「下一站」不會錯位。
- 只能用英文字母、數字、`-`、`_`，最多 40 字，整份行程不能重複。例如 `d1-airport`、`d2-dazaifu`。
- 沒填的列照舊用「日期＋第幾列」。旅程開始後**不要再改已填的行程ID**，否則已打卡的站會變回未打卡。

## 五、檢查連結時的錯誤訊息

| 訊息開頭 | 原因與處理 |
|---|---|
| 這是編輯連結 | 改用第二節第 6 步「發布到網路」產生的連結 |
| 看不懂這個連結 | 連結不完整，重新複製 |
| 無法下載這份試算表 | 手機沒網路，或試算表還沒「發布到網路」 |
| 試算表內容不符合範本 | 某個分頁的標題列被改過或缺欄位；訊息後面會寫哪一頁 |
| TripConfig 的 Trip ID… | Trip ID 沒填或格式不對 |
| TripConfig 的 Ledger Endpoint… | 網址不是 `https://script.google.com/macros/s/…/exec` |
| TripConfig 的 Start Date／End Date… | 日期格式要 `YYYY-MM-DD` |
| TripConfig 的 Currency… | 要是三個英文字母的幣別代碼，例如 `KRW`、`USD` |
| TripConfig 的匯率… | 有填的話匯率要大於 0（也可以不填）；結算幣別只能是台幣或這趟的當地幣別 |
| 無法連到這份試算表的 Apps Script | 還沒部署成網頁應用程式，或存取權設錯 |
| Ledger Endpoint 屬於另一份試算表 | Endpoint 貼成別份試算表的網址（例如範本或岡山的）；換成這份自己部署的網址 |
| 「分帳紀錄」分頁的標題列和範本不一致 | 分帳紀錄第一列被改過；從範本複製回來 |

任何一步失敗，手機都不會改變，修好試算表後再按一次「檢查連結」即可。

## 六、發布時機（給 Bar）

v150 讓「沒有任何紀錄的手機」顯示「尚未連接旅程」。為了讓 v150 能在岡山旅程前上線（Bar 2026-10-11 決定），加了「岡山保護期」：

1. 台灣時間 **10/24 00:00 以前**第一次打開 v150 的手機，就算還沒打卡、沒記帳，也會沿用岡山行程。之後會一直是岡山，直到自己「清除並打包旅程」。
2. 10/24 以後才第一次打開、手機上又沒有任何紀錄的人（例如刪掉 App 重裝），會看到「尚未連接旅程」，**接不回岡山**。所以岡山的帳請在旅程中或結束後盡快用原本的手機結清，不要重裝 App。
3. 岡山結清後，各自「清除並打包旅程」，再照第三節連接下一趟。

## 七、備份與封存

- v150 的個人備份會記下是哪一趟旅程；還原時旅程不同會被拒絕。舊版（v149 以前）的備份只能還原到岡山旅程。
- 封存到 Drive 的檔案會記下 `sheet:<Trip ID>`，不同旅程不會混在一起。

## 附錄：岡山旅程固定天氣城市的座標來源

岡山舊旅程不讀「天氣地區」分頁，改用程式內的固定城市清單（`WEATHER_CITIES`）。v154–v156 的 App 程式註解寫「來源見 `docs/trippilot-v146-verification.md`」；該驗證文件已於 2026-10-16 經 Bar 核准刪除（git 歷史仍保留），來源改記於此（內容摘自原文件「區域來源及限制」一節）。

- 代表座標是區域中心，不是精確站點 GPS，也不代表沿途微氣候。既有岡山／倉敷共用區域維持；v146 新增尾道、福山、祖谷、琴平、丸龜。祖谷涵蓋大／小步危，宇多津與呆呆獸公園採鄰近丸龜的代表區域。
- [尾道觀光協會千光寺](https://www.ononavi.jp/sightseeing/temple/detail.html?detail_id=9)核對區域。尾道 `34.41667,133.2`、廣島福山 `34.48333,133.36667`、香川琴平 `34.18333,133.81667`、丸龜 `34.28333,133.78333` 由 [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) 在開發時只讀查證，選 JP 且行政區相符的結果；App 沒有因此多呼叫任何 API。
- 祖谷 `33.87513,133.8251` 為[三好市官方祖谷藤蔓橋](https://miyoshi-tourism.jp/en/spot/46/)地圖中心；[琵琶瀑布官方資料](https://miyoshi-tourism.jp/spot/88/3/)核對區域關係。
- [香川縣觀光協會金刀比羅宮](https://www.my-kagawa.jp/konpira/feature/kotohiragu/guide3)核對琴平區域；城市代表點不是山頂的精確預報。
