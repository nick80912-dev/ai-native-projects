# 不限日本：幣別、稅、天氣與收據辨識（設計）

> 2026-10-31。來源：Bar「該專案未來不只回去日本，有可能會去其他國家，所以內容需要修正一下比方幣別切換與辨識等，不受限於日本」。
> 狀態：設計已定案（Bar 2026-10-31 的裁定見 §1），依 §6 分批實作，每批一版、逐版送 main 給 Bar 手機審查。

## 1. Bar 的裁定（2026-10-31）

| 問題 | 裁定 |
|---|---|
| 結算用的本國幣別 | **一律台幣（TWD）** |
| 一趟旅程的當地幣別 | **一趟一種**（例如韓元、泰銖、歐元），記帳在「當地幣別／台幣」間切換，跟現在日幣／台幣一樣 |
| 稅 | **每趟自己設定**稅率與價格預設含稅或未稅；不需要的旅程不顯示稅的選項；日本旅程維持現在的樣子 |
| 有小數的幣別（美金、歐元） | **記到分**（$12.50 記 12.50）；日幣、韓元、台幣這類沒有小數的仍是整數 |
| 順序 | **先改成不限日本，再做 #61 收據辨識**（#61 併入讀收據上的日期時間，Bar 2026-10-31） |
| 試算表沒填匯率 | **可以，在手機上補填當作基準**（Bar 2026-10-31）：存下的匯率寫回試算表 TripConfig，全團共用 |

## 2. 現況：綁在日本的地方

- **幣別**：分帳紀錄的欄位叫「日幣」「台幣」（`schema.js`、`apps-script/ledger-sync.gs` 的 `HEADERS`）；Apps Script 只接受 `JPY`／`TWD`；App 內 `amountJpy`／`amountTwd` 約 230 處、`'JPY'`／`'TWD'` 約 160 處、`¥`／`NT$` 約 30 處；`Exchange Rate` 定義為「1 JPY 對應的 TWD」；金額一律整數（`isSafeLedgerInteger`）。
- **稅**：8%／10%、税込／税抜、免稅、優惠券的計算都照日本規則寫死。
- **天氣**：Open-Meteo 請求寫死 `timezone=Asia/Tokyo`，每小時資料補 `+09:00`。
- **預設內容**：支付方式預設含 `Suica`；ADR 0021 寫「只支援日本（JPY↔TWD、天氣時區 Asia/Tokyo）」；`docs/new-trip-handbook.md` 的 TripConfig 範例是 JPY。
- **時間**：v165 起一律跟手機時區（Bar 2026-10-30），不需再改。

## 3. 設計

### 3.1 TripConfig

| Key | 意義 | 沒填時 |
|---|---|---|
| `Currency` | 當地幣別，ISO 4217 三碼（`JPY`、`KRW`、`THB`、`USD`、`EUR`…）。這個 key 已在 schema 裡、目前沒有用到 | `JPY`（岡山與舊試算表不變） |
| `Exchange Rate` | **1 單位當地幣 = 多少台幣**（例如 KRW `0.024`、USD `32.1`） | **可以不填**（§3.1.1） |
| `Ledger Default Currency` | 全團結算幣別：當地幣別代碼或 `TWD` | 這趟的當地幣別 |
| `Tax Rates`（新，選填） | 這趟的稅率，逗號分隔，例如 `10,8`；填 `0` 或留空＝不顯示稅的選項 | 當地幣別是 `JPY` 時視為 `10,8`（岡山不變），其餘視為不顯示 |
| `Price Mode`（新，選填） | 價格預設 `含稅` 或 `未稅` | `含稅` |
| `Tax Free`（新，選填） | `yes` 才顯示「免稅」選項 | `JPY` 視為 `yes`，其餘 `no` |

#### 3.1.1 匯率可以在手機上補填（Bar 2026-10-31）

- 現況：TripConfig 沒有 `Exchange Rate` 時，`validator.js` 判為 blocker（整份試算表不載入），`trip-source.js` 連接新旅程也會失敗。
- 改為：沒填不擋載入與連接。還沒有匯率時，記帳表單提示「請先設定匯率」並帶到「設定 → 分帳設定」；存下後照現有的分帳設定同步（Apps Script `updateSettings` 寫回 TripConfig 的 `Exchange Rate`／`Ledger Default Currency`，v161 的橋接規則照舊），**全團共用同一個基準**。之後誰改匯率也一樣同步。
- 填之前已經存在的紀錄不受影響（紀錄本身存了當地幣與台幣兩個金額）。

### 3.2 金額：內部用「最小單位」

- 每個幣別有小數位數：`JPY`／`KRW`／`TWD`／`VND`／`IDR` 為 0；`USD`／`EUR`／`THB`／`HKD`／`SGD`／`GBP`／`AUD`／`CNY`／`MYR`／`PHP` 為 2；其餘依 `Intl.NumberFormat(...).resolvedOptions().maximumFractionDigits`。台幣一律 0（實務上不用角）。
- App 內部的金額一律是**整數的最小單位**（美金存「分」），既有的整數運算、分攤與結算演算法不變。只在邊界轉換：讀試算表 CSV／fast pull、送 Apps Script、表單輸入、畫面顯示、匯出。
- 試算表上寫的是一般金額（`12.5`），Bar 在試算表看到的就是實際金額。小數位數 0 的幣別（含岡山的 JPY）前後完全相同，**既有資料不需要轉換**。
- 內部欄位名稱 `amountJpy`／`amountTwd` 與送 Apps Script 的鍵**維持不變**（意思改為「當地幣金額」／「台幣金額」），避免改動 230 處與舊版 Apps Script 不相容；`schema.js` 與文件寫清楚新意思。
- 內部的幣別代號同樣沿用 `'JPY'`／`'TWD'`，代表「當地幣別」／「台幣」兩個槽位（v168 實作：`ledgerCurrencyCodeOf()`／`ledgerCurrencyTokenOf()`），只在畫面、試算表與 Apps Script 換成真正的代碼。
- 新試算表範本的欄位標題改成「當地幣」「台幣」；App 同時認「日幣」與「當地幣」（schema `aliases`）。Apps Script 依位置寫入，標題文字不影響寫入。

### 3.3 顯示

- 幣別表：代碼 → 中文名稱與符號（JPY 日圓 ¥、KRW 韓元 ₩、TWD 台幣 NT$、USD 美元 US$、EUR 歐元 €、THB 泰銖 ฿、HKD 港幣 HK$、CNY 人民幣 CN¥、SGD 新加坡幣 S$、GBP 英鎊 £、AUD 澳幣 A$、VND 越南盾 ₫、PHP 披索 ₱、MYR 令吉 RM、IDR 印尼盾 Rp）；不在表上的用代碼。
- 所有「日幣」「¥」字樣改由目前旅程的幣別產生；小數幣別顯示到兩位（`US$12.50`）。

### 3.4 Apps Script

- `inputCurrency`：接受 `^[A-Z]{3}$`；結算幣別：接受 TripConfig `Currency` 或 `TWD`。
- 金額驗證改為「有限數字、最多兩位小數」。
- 舊的岡山部署不必重新部署也能繼續用（JPY 整數）；**新旅程**要用新版 Apps Script（由 AI 寫好、Bar 貼上部署）。

### 3.5 稅

- 稅率選項、價格預設與免稅依 §3.1；沒有稅率的旅程，記帳表單不顯示稅的區塊，金額就是實付。
- 日本旅程（`JPY` 且沒填新 key）畫面與計算完全不變。

### 3.6 天氣

- Open-Meteo 改用 `timezone=auto`，每小時資料用回應的 `utc_offset_seconds` 換成真正的時間點，不再補 `+09:00`。

### 3.7 預設內容與文件

- 新旅程的支付方式預設 `現金、信用卡、行動支付、其他`（已存在手機上的清單不動，岡山的 Suica 照舊）。
- ADR 0021 增補「不限日本」；`docs/new-trip-handbook.md` 的範本與檢查表改成任何國家；`03_DATABASE.md` 寫明金額欄位的新意思與小數規則。

### 3.8 #61 收據辨識（之後）

- 雲端 AI 一次讀出收據上的**日期、時間、金額、幣別、店名**；讀到收據上的時間就用收據時間（標示「依收據上的時間」），讀不到才用拍照時間（v167）。
- 讀到的幣別和這趟的當地幣別不同時提醒。不限語言與國家。
- 動工前 Bar 要申請 API 金鑰，並確認辨識時照片會傳到雲端一次。

## 4. 相容性

- 岡山試算表、既有紀錄、個人帳、備份與已安裝的手機：`Currency` 沒填 → `JPY`、小數位數 0 → 數值、計算、畫面都和現在相同。每一版都用現有的岡山測試資料跑完整測試確認。
- 個人備份格式（v10）不變：金額仍是當地幣與台幣兩欄；小數幣別的備份存最小單位，備份另記 `currency` 讓還原時檢查（版本升 v11 時另寫相容策略）。

## 5. 測試

- 每版：四個 gate、全部 Node 測試、本機完整 Chromium、CI。
- 新增：韓元（0 位）、美金（2 位）旅程的記帳、多品項、稅、分攤、結算、還款、匯出與顯示；岡山（JPY）回歸不變；Apps Script 接受任何三碼與兩位小數。
