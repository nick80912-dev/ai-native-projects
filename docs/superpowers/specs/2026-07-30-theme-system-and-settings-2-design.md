# 主題系統、設定頁 2.0 與旅途紀錄設計

> 2026-07-30 經 Bar 逐項確認。對應 `tasks/backlog.md` #3b、#6、#7、#8、#9。
> 目標版本為 SW v72；開發仍以前置條件完成後才開始。

## 目標

1. 提供六組可擴充的淺色主題，海洋／岡山維持預設。
2. 將設定頁改為較短、可返回且可保存捲動位置的混合式資訊架構。
3. 將四個主頁籤與設定入口由平台相依 Emoji 改為一致的線條 SVG。
4. 讓 Bar 在旅途中從既有診斷面板快速記錄異常與 UI／UX 優化建議。
5. 個人備份升 v8，一次補入主題、採買單位與旅途紀錄。

## 不可變邊界

- Ledger Schema 維持 2.9；不修改 append-only 更正／作廢、canonical conflict、結算、付款人身分或權限。
- 不新增雲端欄位、工作表、Apps Script action 或 TripConfig 白名單。
- 成員 canonical 名稱不可改名或刪除；成員介面只允許列出、切換與新增。
- 桃子徽章與內容區 Emoji 保留；只替換四個主頁籤與設定入口共五個功能圖示。
- 深色模式、全站硬編碼色全面 token 化、主題跨裝置同步不在本批。

## 二、主題行為與選擇器

- 以單一 registry 保存六組 ID、顯示名稱、token 與 chrome 色。
- `themeId` 保存於本機；不寫 TripConfig、不影響其他成員。
- 啟動時先驗證 ID；缺值或未知 ID 回退 `ocean`。
- 點選主題卡立即套用並保存。保存失敗時恢復上一主題、保留子頁並提示，不顯示假成功。
- 設定首頁「主題」列顯示目前名稱、迷你色彩介面與「6 組主題」。
- 點入獨立主題 Sheet，使用雙欄「迷你介面卡」：卡片呈現頁面底、頂欄、主要色、強調色、名稱與勾號。
- 不顯示「只影響這台裝置」或「成熟俐落」等說明文案。
- 未來新增主題只新增 registry 項目；雙欄網格自然延伸，不使用橫向輪播。

## 三、Emoji 與線條 SVG

- 替換範圍：今天、行程、購物、分帳四頁籤的 `🏠🗺️🏬💴`，以及右上設定 `⚙`。
- 採同系列 MIT outline SVG，內嵌於 `index.html`；`viewBox="0 0 24 24"`、`stroke="currentColor"`、`stroke-width="1.75"`。
- 不引入 webfont、外部 CDN 或額外線上依賴。
- 選中頁籤使用 `--sea-deep`、頂部指示條與字重，不使用 `--coral`，避免只靠顏色。
- 分帳 `tabbar-badge` 改定位在 SVG 容器，未同步筆數行為不變。
- 桃子徽章 PNG、交通、警告、狀態、類別等內容 Emoji 全數保留。
- 每個純圖示按鈕必須保留可讀 `aria-label`。

## 四、設定頁 2.0

### 最終順序

| 區段標題 | 內容 |
|---|---|
| 身分 | 精簡目前身分卡、切換、新增 |
| 主題 | 目前主題摘要與主題子頁 |
| 代購對象 | 對象數量摘要與獨立管理子頁 |
| 帳務 | 匯率、預設幣別、簡易結算模式 |
| 自訂項目 | 類別、支付方式、採買單位及未來同型自訂項目 |
| 資料與版本 | 備份／還原、SW 版本、最近 5 筆使用者更新 |
| 測試模式 | 團體帳測試模式行內開關，固定置底 |

診斷面板不出現在設定清單；入口維持桃子徽章連點兩下。

### 身分卡

- 保留現有 canonical 行為，不新增「管理／改名／刪除」。
- 左側顯示小標「目前身分」與完整 canonical 名稱；右側同一列放「切換」「新增」。
- 320px 下長名稱只做視覺省略，不改原值；兩顆按鈕維持至少 38px 高。
- 切換與新增仍沿用現有 member selector 與 `identity_registration` 契約。

### 混合式子頁

- 主頁只直接操作身分切換、簡易結算與測試模式。
- 匯率／幣別、主題、代購對象、自訂項目、備份／版本進獨立 Sheet。
- 子頁沿用既有 Sheet／返回模式，不建立第三種導覽樣式。
- 設定主頁與子頁保存 scrollTop 與返回 context。新增、刪除或排序後重繪不得跳回頂端。
- 每個摘要值直接取既有 store／設定，不建立第二份資料來源。

## 七、診斷面板與旅途紀錄

### 入口與用途

- 診斷面板保留，入口仍為桃子徽章連點兩下。
- 新增「旅途紀錄」區，供 Bar 即時記錄異常與 UI／UX 優化建議。
- 旅途紀錄不得觸發修正資料、修改權限或繞過任何 fail-closed 防護。

### 每筆資料

| 欄位 | 規則 |
|---|---|
| `id` | 本機穩定 ID |
| `kind` | `issue`（異常）或 `suggestion`（優化建議） |
| `text` | 必填，1–500 字 |
| `status` | `pending`（待評估）或 `resolved`（已處理） |
| `createdAt` | 首次建立時間 |
| `updatedAt` | 最後修改時間 |
| `view` | 儲存當下頁面 |
| `appVersion` | `APP_VERSION` |
| `online` | 儲存當下線上／離線 |
| `syncState` | 儲存當下同步狀態 |
| `healthSummary` | 精簡 healthCheck 結果，不含完整 AppLog |

### 操作

- 表單提供「異常／優化建議」切換與 500 字文字欄。
- 最新優先，可依類型篩選，並可切換「待評估／已處理」。
- 允許修改文字；刪除必須二次確認，`createdAt` 不變、修改更新 `updatedAt`。
- 可複製人類可讀摘要與 JSON；同時納入備份 v8。
- 上限 200 筆。達上限時不自動刪除，要求先匯出或清理。
- localStorage 寫入失敗時保留表單與舊清單，顯示錯誤，不顯示假成功。
- 不保存完整 AppLog；既有「複製診斷報告」仍處理即時完整診斷。

## 八、錯誤處理

- 無效主題啟動時靜默回退海洋色並記錄診斷；互動保存失敗則明確提示。
- 子頁操作失敗留在原頁並保留輸入與 scrollTop。
- 版本來源缺失視為開發／測試錯誤，CI 必須失敗；runtime 顯示不得猜測版本。
- v8 還原與旅途紀錄保存皆不得部分提交。
- 所有新增本機資料都必須處理 storage denied／quota exceeded。
