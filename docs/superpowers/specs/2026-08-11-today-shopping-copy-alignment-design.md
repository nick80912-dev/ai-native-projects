# Today 採買摘要語意與通用動作對齊設計

> 日期：2026-08-11
>
> 狀態：設計已確認，等待書面規格審閱
>
> 基準版本：App／SW v103 `dev`

## Purpose

讓 Today Hero 右側採買摘要在視覺與語意上保持一致：通用狀態的「開啟查看 →」應與右側採買內容靠右；`順路採買` 與 `今日採買` 則維持方向感不同、但都能指向具體行程站點的既有判定。

## Confirmed Decisions

- 只調整通用採買摘要的 value 對齊，不移動整個按鈕，也不改 44px 點擊區、Hero 欄寬、分隔線或地名省略。
- `順路採買` 僅用於目前站之後第一個有待買項目的有效行程站。
- `今日採買` 表示今天仍有綁定行程站的待買項目，但無法誠實保證該站位於接下來路線上。
- `今日採買` 仍顯示第一個有效站點名稱與該站待買數量，點擊後聚焦該站群組。
- 若目前站無法解析，即使所選站點看似位於行程後段，也使用中性的 `今日採買`，不推測為 `順路採買`。
- 若所有待買項目都在目前下一站，Hero 不重複顯示；入口維持下一站卡既有採買徽章。
- 未綁定、失效或混合未解析項目無法形成有效站點摘要時，顯示通用入口 `採買清單｜開啟查看 →`。
- 本次不新增狀態、API、schema、storage key、版本號或資料遷移。

## Decision Table

| 條件 | Hero 標籤 | Hero 內容 | 點擊結果 |
|---|---|---|---|
| 目前站之後有有效待買群組 | `順路採買` | 第一個未來站點名稱 · 該站 `N 項 →` | 開啟並聚焦該站群組 |
| 只有過去站點待買 | `今日採買` | 第一個有效站點名稱 · 該站 `N 項 →` | 開啟並聚焦該站群組 |
| 目前站無法解析，但仍有有效站點待買 | `今日採買` | 第一個有效站點名稱 · 該站 `N 項 →` | 開啟並聚焦該站群組 |
| 所有待買都屬於目前下一站 | 不顯示 Hero 採買摘要 | 下一站卡徽章負責提示 | 徽章開啟該站群組 |
| 沒有可形成站點摘要的未完成項目 | `採買清單` | `開啟查看 →` | 開啟完整採買清單 |

## Visual Contract

- `.today-hero-shopping-generic .today-hero-summary-value` 的內容靠右。
- `採買清單` 標籤與「開啟查看 →」同屬右側摘要欄，兩行右緣對齊。
- 具體站點摘要維持目前布局：站點名稱可伸縮並省略，`N 項 →` 固定可見。
- 320、375、390px 寬度下不得新增水平溢位或壓縮 44px 操作區。
- 外出提醒、天氣圖示、進度文字、下一站卡與 pre-trip 畫面不變。

## Testing Contract

- 先新增 source/CSS 測試，要求 generic value 使用右對齊的 flex 配置，並觀察 RED。
- Browser 測試在天氣失敗／通用採買狀態下確認「開啟查看 →」的 computed layout 靠右。
- 保留既有純函式測試，繼續鎖定未來站為 `順路採買`、過去或未解析目前站為 `今日採買`。
- 保留下一站徽章不重複、鍵盤操作、長地名省略與 320／375／390px 幾何測試。

## Rollback Boundary

若右對齊造成窄螢幕回歸，只回退 generic value 的對齊 selector 與對應測試；不得回退 v103 Hero、採買投影、天氣提示或下一站徽章權責。
