# Ledger 計算機小數、百分比與即時計算介面設計

> 狀態：Approved direction，等待 Bar 審閱書面規格。2026-08-08 由 Bar 核准採參考圖的四欄計算機介面、購物計算機百分比語意，以及套用時將正數小數結果無條件捨去。

## 目標

將 v92 的共用 Ledger 金額計算器擴充為適合購物與記帳的即時計算機。使用者可以輸入小數與百分比，透過獨立的等號檢視結果，再由「套用金額」寫回目前的單品、多品項或固定折扣欄位。

本批只改計算器 UI、暫存狀態、運算解析與套用 workflow；不改 Ledger schema、同步、備份格式、稅額／分攤推導、Shopping link 或資料儲存格式。

## 方案比較與決策

### A. 只在現有鍵盤補 `.` 與 `%`

改動最小，但無法呈現參考圖的 `AC`、`00`、`=` 與清楚的運算／套用分工。百分比若只視為除以 100，`1000-10%` 會得到 `999.9`，不符合購物心智模型。不採用。

### B. 改為參考圖布局，但每次按鍵立即覆寫單一結果

視覺接近參考圖，但會失去完整算式，連續加總或折扣出錯時難以核對，也弱化目前 v92 已有的完整算式顯示。不採用。

### C. 四欄即時計算機 + 雙層顯示 + 資料 target workflow

採用。保留既有單一 `ledgerCalculatorState` 與 `{type:'single'|'item'|'discount'}` target，不保存 DOM reference。介面採參考圖的五列四欄鍵盤；顯示區以小字保留算式、大字顯示結果；`=` 只結算並留在計算器，「套用金額」才寫回 Ledger 草稿。

## UI

Bottom Sheet 標題改為「計算金額」，右上角提供至少 44×44px 的明確關閉按鈕。點擊背景不關閉；Escape、右上關閉與底部取消都不修改原金額。

顯示區分兩層：

- 上層顯示完整算式，長內容水平安全截斷或捲動，不造成頁面 overflow。
- 下層以大字顯示目前結果。
- 若結果有可捨去的小數，補充顯示「將套用 ¥N」或「將套用 NT$N」。
- 錯誤訊息使用既有 `aria-live` 區域；結果變化保持可被輔助科技感知。

鍵盤固定為五列四欄：

```text
%    AC   ⌫    ÷
7    8    9    ×
4    5    6    −
1    2    3    ＋
.    0    00   =
```

底部保留「取消」與主動作「套用金額」。每個按鍵是正式 button，實際觸控區至少 44×44px；320、375、390px 均不得水平溢出。配色沿用目前 App theme token，不複製參考圖的固定色碼。

## 輸入與等號狀態

- `.` 只作用於目前數字；同一數字已有小數點時不再新增。
- 空值按 `.` 產生 `0.`；運算子後按 `.` 也產生下一個運算元 `0.`。
- `00` 一次輸入兩個零；目前數字為單一前導 `0` 時不得形成無意義前導零。
- `AC` 清除算式、結果與錯誤，但不修改 Ledger 原金額。
- `⌫` 每次移除一個輸入 token／字元，百分比視為一個 postfix token。
- 連續按運算子時，以最後一個運算子取代前一個，延續 v92 行為。
- `=` 計算目前算式，結果留在計算機且不寫回 Ledger。之後按數字或 `.` 開始新算式；按運算子則以該結果繼續計算。
- 「套用金額」可直接套用目前有效的即時結果，不強迫先按 `=`。

## 百分比語意

`%` 是 postfix 百分比，只能接在完整數字或已完成的運算結果後。採購物計算機的 contextual percent：

| 輸入 | 結果 |
| --- | ---: |
| `10%` | `0.1` |
| `1000×10%` | `100` |
| `1000÷10%` | `10000` |
| `1000＋10%` | `1100` |
| `1000−10%` | `900` |

加減百分比以當下左側已計算金額為基準，因此 `1000+10%+10%` 依序得到 `1100`、`1210`。乘除百分比則把百分數作為比例值。連續 `%`、運算子後直接 `%` 或不完整小數後 `%` 必須拒絕並顯示明確錯誤。

實作必須使用明確 tokenizer／parser／evaluator，不得使用 `eval()`、`Function()` 或將算式交給 DOM／URL 執行。

## 小數顯示與套用規則

運算元、中間結果與顯示結果可以有小數。顯示沿用可讀的千分位格式，最多顯示 12 位小數，去除尾端無意義的零。

套用規則如下：

- 正數整數：原值套用。
- 正數小數：以 `Math.floor()` 語意無條件捨去後套用。
- 單品／多品項結果捨去後若為 `0`：阻止套用，顯示「捨去後金額必須大於 0」。
- 固定折扣結果捨去後為 `0`：允許套用，維持既有折扣零值政策。
- 負數、非有限值、除以零或超出 `Number.MAX_SAFE_INTEGER`：阻止套用。

為避免 IEEE-754 誤差把數學上的整數（例如內部值 `2.9999999999999996`）錯捨為前一個整數，套用前只校正落在浮點誤差容限內的近整數；真正的小數仍一律向下取整，不做一般四捨五入。

範例：

| 算式結果 | 寫回值 |
| ---: | ---: |
| `1512` | `1512` |
| `1512.9` | `1512` |
| `0.9`（一般金額） | 阻止 |
| `0.9`（折扣） | `0` |
| `-1.2` | 阻止 |

## State 與資料流

沿用單一暫存 state，增加等號後輸入判斷所需的明確欄位；不得建立每個表單各自的計算器：

```js
ledgerCalculatorState = {
  open: false,
  target: null,
  expression: '',
  originalValue: '',
  result: null,
  error: '',
  evaluated: false,
  sheetScrollTop: 0
};
```

資料流為：按鍵 → tokenizer／輸入 reducer → evaluator → 顯示 model → 套用正規化 → 依 target 走既有 `updateLedgerDraftField()` 或 `updateLedgerDraftItem()`。套用時重新解析 live draft 與 item key；stale target 必須 fail closed，不得寫入其他欄位。

開啟計算器後 Ledger entry sheet 保持 mounted 並設為 inert，關閉時恢復捲動位置與原金額欄焦點。其他草稿資料，包括店名、品名、代購、分攤、稅率、日期與 Shopping source identity，均不得遺失。

## 測試

先更新測試並證明在 v93 runtime 上失敗，再實作：

- Node：小數 tokenizer、單一小數點、前導 `0.`、`00`、四則優先序、除零、安全範圍、百分比五種基準案例、連續百分比、等號後續輸入、正小數 floor、近整數浮點校正、一般金額與折扣的零值差異、stale target。
- DOM/source contract：五列四欄、`%`／`.`／`00`／`=`／`AC`／關閉按鈕、aria-label、觸控尺寸、無動態程式執行。
- Playwright：單品、多品項、折扣、採買轉記帳、編輯／更正；取消不修改、等號不關閉、套用後換算預覽更新、焦點／scroll／inert／Escape、Tab focus trap。
- Viewport：320px、375×844、390px；按鍵、顯示區、底部動作均無水平 overflow，短高度時 sheet 可安全垂直捲動。
- 回歸：完整 Node tests、完整 Playwright、文件標題、版本一致性與 `git diff --check`。
