# 設定「自訂項目」資訊架構整理設計

> 日期：2026-08-11
>
> 狀態：A 方案已核准，等待書面規格確認
>
> 基準：App／SW v103 `dev`

## 目的

目前「自訂項目」子頁將記帳類別、支付方式、採買單位三組管理器全部展開在同一頁。預設資料共有 24 列，每列又同時顯示上移、下移與刪除操作，造成頁面過長，使用者進入後難以快速判斷三組內容的邊界。

本次採用已確認的 A 方案：把「自訂項目」改為摘要入口頁，再讓每一類進入自己的管理頁。目標是降低單一畫面的資訊密度，不改變新增、刪除、排序、保存或既有紀錄的語意。

## 已確認設計

### 第一層：自訂項目入口頁

`自訂項目` 頁只顯示一句輔助文字與三個可點擊列表入口，固定順序如下：

1. `記帳類別`：右側顯示即時數量，例如 `7 項`。
2. `支付方式`：右側顯示即時數量，例如 `5 項`。
3. `採買單位`：右側顯示即時數量，例如 `12 項`。

入口頁輔助文字固定為：

```text
依用途選擇要管理的項目。
```

每列使用既有設定群組列的視覺語言：左側圖示與標題、右側項目數量與 chevron。整列皆可點擊，最小高度不得低於既有設定導覽列；不新增卡片內的編輯控制。

三個數量都必須在渲染時直接讀取現有 store，不能另建快取或新的持久化欄位。從管理頁返回後，入口頁數量立即反映最新值。

### 第二層：單類管理頁

三個入口分別開啟專屬管理頁：

| 頁面 ID | 標題 | 使用的既有資料種類 |
|---|---|---|
| `options-category` | `記帳類別` | `category` |
| `options-pay-method` | `支付方式` | `payMethod` |
| `options-shopping-unit` | `採買單位` | `shoppingUnit` |

每個管理頁只渲染一個既有 `renderLedgerOptionManager(kind, title)` 管理器。原有功能與順序全部保留：

- 顯示目前所有項目。
- 上移與下移。
- 刪除。
- 最多 6 個字的新增輸入。
- 新增後立即重繪。
- 刪除選項不影響既有紀錄。
- `個` 仍是不可刪除的既有預設採買單位；沿用目前的防護與提示，不改資料規則。

管理頁的說明只描述共通行為：

```text
可新增、刪除或排序；刪除選項不影響既有紀錄。
```

`採買單位` 頁可在 `個` 的項目文字旁標示 `預設`，讓不可刪除規則在操作前可見；刪除按鈕與既有 guard／toast 行為維持不變，避免產生第二套規則。

## 導覽與狀態

- 設定根頁的 `自訂項目` 入口仍開啟 `options`，既有摘要 `N 類別 · N 支付方式` 不變。
- Legacy target `ledgerOptionSettingsSection` 仍解析到 `options` 入口頁，不直接跳入任一管理頁。
- `SETTINGS_PAGE_IDS` 納入三個新頁面 ID。
- `options` 入口頁的返回鍵回設定根頁。
- 三個管理頁的返回鍵回 `options` 入口頁，不直接跳回設定根頁。
- 瀏覽器／PWA 返回流程仍沿用目前 Settings 內部導覽，不增加 URL、history 或新的全域 router。
- 頁面重繪後維持目前 `settingsUiState` 與 scroll 保存方式；新增、刪除、排序後不得意外跳回入口頁或設定根頁。
- 關閉設定 Sheet 再重新開啟時，沿用目前行為回到設定根頁，不保存「上次編輯哪一類」的新偏好。

## 資料與錯誤處理

- 沿用 `ledgerOptionStoreForKind()`、`addLedgerOptionFromSettings()`、`removeLedgerOptionFromSettings()`、`moveLedgerOptionFromSettings()`；不複製 CRUD 邏輯。
- 不修改 category、payment method 或 shopping unit 的 localStorage key、預設值、驗證規則、排序格式或備份格式。
- 不修改記帳表單與採買表單讀取選項的方式。
- 既有重複值、空值、長度、儲存失敗與不可刪除項目的提示行為維持原樣。
- 新頁面只接受上表三個固定 page ID；未知 ID 仍由現有設定頁正規化邏輯安全回退。

## 視覺與可存取性

- 入口頁沿用現有主題 token、設定群組卡、分隔線、chevron 與陰影，不新增硬編碼主題色或外部圖示套件。
- 三個入口各有可理解的可存取名稱，並支援鍵盤 Enter／Space 啟用。
- 管理頁的返回控制有明確可存取名稱，例如 `返回自訂項目`。
- 既有上移、下移、刪除、新增控制的可存取名稱與鍵盤行為不得退化。
- 320、375、390px 寬度下不得水平溢位；項目名稱與控制列不得互相遮蓋。
- 六個既有主題下，標題、摘要、說明、分隔線與控制都必須可讀。

## 範圍限制

本次只做：

- `自訂項目` 入口頁的三類摘要列表。
- 三個單類管理頁與兩層返回導覽。
- `採買單位` 的 `個` 顯示 `預設` 提示。
- 對應的 Node 契約測試、Playwright 互動與窄螢幕測試。

本次不做：

- 不改新增、刪除、排序與保存功能。
- 不改選項預設值、資料 schema、localStorage、備份或還原。
- 不增加搜尋、批次操作、拖曳排序、重設預設值或重新命名功能。
- 不改設定根頁其他群組、記帳流程、採買流程、Today Hero 或 Service Worker 策略。
- 不調整 App／SW 版本號、使用者更新紀錄或發布狀態；本次是 v103 `dev` 的介面整理。

## 測試與驗收

### Node 契約

- `renderSettingsOptionsPage()` 只輸出三個固定順序入口，不再同時輸出三個管理器。
- 每個新 page ID 只對應正確的 kind 與標題。
- `SETTINGS_PAGE_IDS`、頁面 render dispatch 與返回目標涵蓋 `options-category`、`options-pay-method`、`options-shopping-unit`。
- 根頁 `自訂項目` 摘要與 legacy target 契約保持不變。
- 既有 add／remove／move 與 store 測試保持通過。

### Browser 驗收

1. 從設定根頁進入 `自訂項目`，依序看見 `記帳類別`、`支付方式`、`採買單位` 與各自即時數量。
2. 點進每個入口，只看見該類管理器，不出現另外兩類項目。
3. 在單類管理頁新增一項，返回入口頁後數量加一；再次進入時新項目仍存在。
4. 上移、下移、刪除行為維持既有結果；既有紀錄不受刪除影響。
5. `採買單位` 的 `個` 顯示 `預設`，嘗試刪除仍走既有保護提示。
6. 管理頁返回 `自訂項目`，入口頁再返回設定根頁。
7. 320、375、390px 與六個主題無水平溢位、控制遮蓋或無法點擊。
8. 完整 Node、Playwright、文件標題、版本一致性、runtime assets、manifest JSON 與 `git diff --check` 全部通過。

## 回退邊界

若兩層導覽在窄螢幕、返回或設定狀態保存上產生回歸，只回退 `options` 入口頁、三個 page ID、相關樣式與測試。不得回退或改寫既有自訂項目 store、CRUD、防護提示、備份資料或其他設定頁。

## 決策摘要

採用 A「分類入口＋獨立編輯頁」。使用者先看到三種用途與數量，再專注管理其中一類；代價是多一次點擊，但可消除目前 24 列同時展開的長頁與操作噪音。功能、資料與發布版本均維持不變。
