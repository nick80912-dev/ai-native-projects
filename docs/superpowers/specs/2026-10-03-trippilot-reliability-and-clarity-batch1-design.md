# TripPilot 第一批：可靠性與資訊清晰度設計

日期：2026-10-03。狀態：**書面設計待使用者審閱；不是實作或發布核准。**

## 1. 目標與基準

先讓目前旅行使用更可靠、更容易理解，不擴大為旅遊平台。使用者選定的 17 項改善依階段處理，本設計涵蓋第 1、4、6、7、8、9、10 項，以及第 2 項的字體與無障礙盤點。第 3、16 項另做唯讀核對，不以撰寫設計視為已完成核對。

程式閱讀基準為 v141，dev `2362fd6`、main `ead11ff`；兩者 runtime 相同，dev 有額外文件。這次只增加設計及索引文件，不改程式、資料、OAuth、版本或部署。未重新執行完整 App QA，也未補驗 iPhone／Android 實體 PWA。

使用者的尺寸限制優先：**只處理確實難讀的輔助文字，不全站放大；保持目前操作密度與視覺。** 主要標題、金額、按鈕、輸入框不因本案全面增大。先呈現候選清單，實作前以實際畫面決定哪些需要調整。

## 2. 方案選擇

採取「沿用資料模型，改善顯示與必要的寫入確認」。優點是改動可拆開、舊備份相容、較容易回歸驗證；缺點是仍保留部分大型 UI 檔與舊路徑，需要明確限制改動邊界。

不採整體視覺重設或先全面拆檔：改善幅度大，但對旅行前的穩定性、操作習慣和驗證成本不利。也不只換文字與顏色：成本低，但無法處理儲存失敗後仍顯示成功的可靠性問題。

## 3. 第一批的三個獨立子批次

| 子批次 | 內容 | 交付界線 |
| --- | --- | --- |
| A：狀態與摘要 | 完成／略過用語、店家與商品區分、部分購買摘要、同步語意、正常照片健康安靜、字體盤點 | 顯示由現有資料推導，不增加持久化狀態 |
| B：本機儲存可靠性 | 舊式打卡與行程進度路徑的成功確認及失敗提示 | 不改所有儲存函式的契約；不宣稱 localStorage 有交易能力 |
| C：天氣資訊 | 城市、取得時間、有效／過期／無資料及未知降雨 | 沿用來源與 3 小時有效期，不增加背景輪詢 |

每個子批次完成回歸與使用者驗收後才往下一批走；不預先指定尚未使用的版本號，也不把設計批准解讀為 main 發布批准。

## 4. A：狀態、店家與商品、帳務摘要

### 4.1 狀態用語

統一相同語意的文字與視覺，但不把不同領域強制合併成同一狀態。

| 領域 | 建議顯示 | 規則 |
| --- | --- | --- |
| 行程 | 未完成、已完成、已略過 | 自動略過保留「自動略過」原因；不能當作完成 |
| 店家 | 想逛店家 | 不代表已買商品或已記帳 |
| 商品 | 待購買、部分購買、已購買 | 使用既有數量與購買配置的計算結果 |
| 帳務關聯 | 未記帳、部分已記帳、已記帳、待確認 | 只有現有解析結果能證明時才顯示；待確認不算成功 |
| 同步 | 已存本機、待送出、伺服器已接收／等待讀回、已從伺服器讀回 | 各階段需要對應證據；沒有證據不往後提升 |

優先使用既有主題的中性、成功、提醒色與圖示，六組配色不重做。狀態不能只靠顏色辨識；同時保留文字。避免每張卡片堆放所有狀態：只顯示該情境需要的摘要，詳細證據收在診斷或展開區。

「伺服器已接收」須有對應送出成功回應；「已讀回」須有現有資料識別／對帳機制的證據，不能只因一般下載完成而標示全部帳務已讀回。**不能宣稱其他旅伴裝置已讀到**；目前沒有對方裝置回報機制。本批不新增該機制，也不修改 Apps Script。

### 4.2 想逛店家與待買商品

沿用現有頁面與資料，不新增導航頁。區塊標題及空白狀態明示「想逛店家」與「待買商品」；必要時加一句「收藏店家不會新增待買商品」。不把店家勾選變成商品購買或帳務操作。

### 4.3 部分購買與帳務摘要

摘要示例：「已買 2／5 件・已買部分中 1 件已記帳」，但只在模型具備可計算數量及單位時使用此格式。資料不足則顯示「部分購買・帳務待確認」，不用猜測數字。商品全部已買不代表全部已記帳。

金額或記帳筆數使用現有關聯解析結果，不直接以連結陣列長度判斷。處理已刪除帳務、數量調整、多筆購買配置與部分關聯；維持現在的數量、金額、幣別、匯率、分攤計算，不因摘要而更改紀錄。

### 4.4 照片健康

既有正常狀態已相對安靜，保留這點，不為了交付而重做。正常時不增加提醒、紅點或自動檢查；使用者進入健康頁仍可查看正常摘要。只有已確認的無效照片參照等問題才顯示修復入口。

瀏覽器不支援容量估算屬於能力限制，不顯示成照片損毀。不得自動刪除孤立照片、改照片備份政策或新增封存照片。

## 5. 字體與無障礙盤點

下表來自 v141 CSS 宣告；不是每個狀態、每個裝置的最終計算字體。實作前核對 cascade 與實際 DOM，避免重複調整或誤改輸入框。

| 候選位置 | 宣告尺寸 | 保守提案 |
| --- | --- | --- |
| 日期星期／旅程分頁副標 | 9.5／10.5px | 有閱讀問題者試 11px |
| 今天摘要標籤／副值 | 9／10px | 試 11px，避免卡片增高過多 |
| 住宿標籤／交通標籤 | 10.5px | 有需要者試 11px |
| 完成相關小徽章 | 10px | 試 11px，維持單行優先 |
| 店家分類、必買、免稅標籤 | 9.5–10px | 試 11px |
| 商品關聯、分類與附加標籤 | 9.5–10.5px | 試 11px，過長可自然換行 |
| 最近帳務的附加字與小徽章 | 8.5–10px | 優先試 11px，檢查兩列摘要 |
| 帳務匯率、代買說明、選項副標 | 9–10px | 有需要者試 11px |
| 回顧筆記時間／狀態、健康摘要 | 10px | 次優先，試 11px |

箭頭、原始診斷資料與版本歷史日期暫不優先放大。主要金額、標題、主操作與既有輸入框維持；不以 11px 覆蓋輸入欄位。12px 僅在 11px 確實仍難讀且版面驗證可接受時個別提出，不設全域最低字級。

驗收包含 320、375、390px 寬度，以及較大系統字體／瀏覽器文字縮放。檢查主要操作是否被擠出、橫向溢出、文字重疊與焦點可見。鍵盤能操作受影響的勾選與展開項目，重新渲染後不無故失焦；螢幕閱讀器可辨識名稱、選取／展開狀態及必要錯誤訊息。

本批不順勢全站加大點擊區或改卡片間距。需要較大的無障礙版面改動時，另外列出問題、影響與提案；不能以完成此次字體盤點宣稱完整無障礙認證。

## 6. B：舊式打卡與進度寫入失敗

### 現況證據

`lsSet` 捕捉例外後主要記錄診斷。`setItemCompletion` 分別寫入 `trip_next_stop_progress` 與 `trip_checks`；自動略過另有後續進度寫入。這代表部分路徑無法可靠區分寫入成功與失敗。此為程式閱讀發現，尚未以實體手機重現容量不足。

### 設計

限定打卡、完成、略過、自動略過及其撤銷路徑。先列出所有相關呼叫點，再以局部可檢查結果的寫入介面處理，不把全 App 的 `lsSet` 改為拋例外。店家願望清單也使用舊式寫入，但不納入此批；後續獨立處理，避免擴張範圍。

1. 由目前狀態計算下一份完整紀錄；自動略過合併計算，不先顯示部分成功。
2. 寫入前保留受影響鍵的原始值與不存在狀態；執行寫入及必要的讀回核對。
3. 全部確認成功才更新成功 UI、撤銷快照與下一站相關狀態。
4. 失敗時嘗試恢復原始值；恢復也失敗則重新讀取實際資料並顯示「紀錄可能未完整儲存」，不能假裝已回到原狀。
5. 提示「這次操作未能儲存，請稍後重試」並保留診斷；提供現有診斷入口，不導向清空資料。自動路徑去重提醒，避免連續彈窗。

localStorage 沒有交易與跨分頁鎖，此方法是局部寫入確認及盡力恢復，**不是資料庫級原子性**。若實作需要新增持久化交易紀錄或更動多分頁協調，須回報並另行批准。不改完成／略過判斷、時間門檻、下一站排序或群組阻擋規則。

## 7. C：天氣城市、時間與資料品質

保留既有 Open-Meteo 來源、請求逾時與 3 小時快取有效期。時間顯示的是手機取得資料的時間，不冒充氣象站發布時間；沿用地點對應，不能用預設城市掩蓋來源不明。

| 情況 | 顯示策略 |
| --- | --- |
| 有效資料、未滿 3 小時 | 城市、溫度、可用的天氣摘要及「更新於 HH:mm」；快取時間取原始 `t`，讀快取不重設時間 |
| 曾有資料但已達 3 小時，更新失敗 | 「天氣資料已過期，暫無最新資料」；不把舊數字當目前天氣 |
| 無有效資料、請求失敗 | 「暫無天氣資料」；可重試，不顯示 0°C／0% |
| 正在載入 | 簡短載入提示，不阻擋行程 |
| 溫度有效但降雨缺值 | 保留溫度，降雨顯示未知或省略；不得補成 0% |

這一批選擇不展示過期數字，以維持既有有效期規則及避免錯誤出發判斷。頁面再次進入時重新判斷 session 中資料年齡，不能因記憶體有狀態就永久視為新資料。不要背景輪詢或無限重試；同一城市併發請求去重，離開頁面後晚到結果不得覆蓋其他城市。

舊快取的 `t` 可作取得時間；缺少可信時間或內容的紀錄視為不可用。降雨未知時，不用未知值產生「適合出發」等保證式摘要。文字與螢幕閱讀器摘要都使用同一有效性判斷。

## 9. 風險、權限與復原

文件變更已獲准。未來 runtime 實作屬 Tier 2／C 級，需於實作計畫列明並取得相應核准：

- 理由：減少誤判狀態、未儲存卻顯示成功，以及未知／過期天氣被當作有效資訊。
- 影響：受影響頁面的文字、少量輔助字體、進度寫入確認及天氣顯示；不更改共用帳務計算或遠端協定。
- 風險：文字換行、焦點／閱讀器退步、局部寫入恢復失敗、快取年齡判斷錯誤。分批交付並加入對應回歸測試。
- 復原：保留已發布 v141 與 predecessor bridge；新 runtime 使用下一個未占用 generation。若需回復，以新的 generation forward-bump 回到已驗證行為，不覆寫凍結版本、不刪 SW、不清除使用者資料。

預期主要改動落在新 generation UI 與相關測試；只有實作計畫證明需要時才增加小型 helper。凍結的 `shell/v141`、root v110 bridge、Schema 與 Apps Script 不在修改範圍。

## 10. 驗收與進入下一步

實作計畫須將以下情境落成具體測試，而非只核對畫面文字：

- A：完成、手動／自動略過、未完成；店家收藏與商品互不替代；零／部分／全部購買及帳務刪除後摘要；送出成功但未讀回、部分下載失敗；照片正常／無容量估算／無效參照。
- B：第一鍵失敗、第二鍵失敗、恢復失敗、讀回不一致、撤銷失敗、自動略過失敗。失敗時沒有假成功訊息，實際儲存狀態與 UI 一致，既有下一站規則不變。
- C：有效快取、3 小時邊界、頁面常駐後過期、無快取、缺失降雨、請求逾時、離頁晚到回應、不同城市快速切換；未知不變零、過期不變新資料。
- 畫面：320／375／390px、長中文與大字體設定、六組主題、鍵盤及閱讀器受影響操作；保留主要操作可見性，不新增水平溢出。
- 發布前依 repo 流程執行完整 Node／browser QA、離線／連線／旅行日、healthCheck／pageerror、SW 換代與 gate；實體 PWA 未驗項目如實保留，不以桌面測試取代。

本文件自審重點：第一批與後續分開；顯示狀態有證據要求；未知值不偽裝有效值；寫入復原不宣稱原子性；字體沒有全域增大；設計、實作及發布三種核准分開。
