# 採買分類自訂與個人備份設計

日期：2026-10-01。

狀態：對話範圍已確認；本書面規格待 Bar 審閱。尚未實作、升版或推送。

## 目的與已確認範圍

在「設定 → 記帳 → 自訂項目」新增第四個子項「採買分類」，位於「採買單位」下方。使用者可在自己的手機新增、刪除及上下排序採買分類，與記帳類別分開管理。

Bar 已確認：個人備份保存分類選項與排序；旅程封存保存旅行的實際內容，不需要新增自訂分類清單與排序。每筆採買原有的分類文字仍屬旅行紀錄，必須保留。

成功條件是使用者可以選擇自訂分類，重新啟動仍保留設定，換手機匯入備份後恢復選項與排序；刪除選項後，既有商品仍能閱讀、編輯及封存，且不丟失分類或記帳關聯。

## 方案選擇

採用「本機分類設定＋個人備份；封存格式不變」。這既可恢復個人設定，又不在唯讀旅行副本新增無回顧用途的選項清單。

不採用「分類設定也納入封存」：沒有已確認的查看需求，且擴充封存白名單會涉及版本與 checksum 相容性。不採用「只存本機、不進備份」：換手機時需要重新設定，且與已確認的個人備份需求不符。

容量效果僅是避免新封存增加這份小型設定資料，不代表已存在的封存會變小。不刪除、重寫、壓縮或重新上傳既有封存，也不移除既有格式已保存的其他設定與八表內容。

## 畫面與操作

- 自訂項目原有前三項的名稱、順序與功能不變；新增「採買分類」及選項數量。
- 管理頁沿用既有新增輸入、上移、下移、刪除與返回模式，不新增拖曳、階層分類、改名或重設預設值按鈕。
- 第一次使用預設依序為「必買、伴手禮、生活用品、其他」。四項都可刪除；空清單是有效設定，不應在重新啟動時自動補回。
- 新選項以字串處理、去頭尾空白，最多 6 個字（沿用現有選項管理的字串長度語意），不接受空白或重複名稱。沿用「代購」的歷史遷移語意，不開放新增同名分類，提示改用既有代購對象功能。
- 分類仍是選填；採買表單按使用者設定順序顯示選項，再點選已選分類可清空。
- 編輯一筆使用已移除分類的商品時，仍顯示其原分類與「已移除選項」說明；未更動分類時保存原值。這個暫時顯示不會把已刪除選項重新加入清單，也不讓新商品選到它。
- 管理頁說明刪除選項不影響既有紀錄。刪除或移動不更新商品分類，不觸發 Ledger 或 Sheet 同步。
- 名稱、HTML 及 inline handler 參數沿用既有 escapeHtml／jsString 邊界，保留鍵盤操作、可及名稱與邊界排序按鈕的 disabled 狀態。

## 資料邊界與錯誤處理

分類選項使用獨立的 `trip_shopping_categories` localStorage key，沿用既有選項 store 與設定路由模式，不能與 `ledgerCategoryStore` 混用。沒有 key 時才使用預設值。

「可供選擇的分類清單」與「商品保存的歷史分類文字」是不同責任。新建或變更分類只能使用當下的有效選項或空值；已保存的商品分類允許空字串，非空分類須為字串、去頭尾空白後最多 6 個字，不因清單移除而變成無效。不得用現行選項 membership 過濾既有商品、丟棄商品或改寫其標籤。保留 `category: '代購'` 的既有空字串遷移規則。

設定寫入失敗時保留先前選項及商品資料，顯示失敗提示，不宣稱成功。讀取損壞設定使用既有安全降級與日誌慣例，不主動覆寫原始 key。重置紀錄保留這份設定；清除目前旅程依既有 trip_* 清理政策清除它。inactive 裝置不因直接呼叫新增分類操作重新建立旅程資料。

不新增跨裝置同步、帳號關聯、Google scope 或 API。清除守門、待同步 Queue、已鎖帳務與採買轉記帳的既有安全邊界不變。

## 個人備份相容性

目前 v9 備份沒有分類選項欄位，依 `docs/personal-state-compatibility.md` 新增 `shoppingCategories` 時升個人備份格式至 v10。此版本與 App／SW generation 版號無關。

- v10 匯出保存當下分類選項與排序；每筆商品仍保存自己的分類字串。不另匯出已刪除選項清單。
- v10 匯入要求分類設定為有效字串陣列，依順序還原；空陣列有效。缺欄位、空白、重複、超長、非字串或不相容名稱均整批拒絕，裝置狀態不變。
- v10 商品的合法歷史分類可以不在匯入的選項清單中，避免「先刪分類再匯出」導致無法還原。商品名稱、數量、allocation／Ledger links 等其他規則不放寬。
- v1–v9 備份缺乏這份設定，保留匯入當下裝置的分類選項與排序；即使舊版 payload 手動夾帶 `shoppingCategories`，仍忽略該欄位。舊版商品維持原有固定分類驗證與遷移語意。
- v11 或更高版本維持整批拒絕；舊 App 拒絕 v10 是既有向前相容政策，不更改舊 App。
- 還原的原子快照與回復範圍由既有 12 個 key 擴充至 13 個，包含新分類 key；所有驗證先完成，寫入任一失敗則回復整批原值。
- 契約文件與真實 store 的 restore matrix 同步更新，不以假 store 或只檢查版本接受作為證據。

## 旅程封存與過往旅程

`trippilot-archive` 維持 version 1，個人白名單欄位順序、checksum 投影、Drive format metadata 及既有封存讀取契約均不變。新增分類選項不進 `lifecyclePersonalData()`、archive 個人白名單或備份以外的雲端資料。

每筆 `shoppingItems[].category` 照原值進入既有封存。過往旅程 renderer 直接閱讀封存商品，不以目前手機的分類清單驗證或重分類。即使目前手機已移除該選項，歷史分類仍顯示。

過往旅程維持旅程選擇、按天行程與打卡、可展開的採買／個人帳／團體分帳／旅途紀錄，以及唯讀封存與追加回顧筆記。既有「完整原始資料」不在本次刪除或重新設計範圍。封存仍不含照片、photoId、token、Queue 或診斷資料。

## C 級與 Tier 2 風險群組說明（實作前確認）

本功能涉及本機資料驗證及備份介面，採 architectural 設計流程與 repo C 級流程。已知悉 `15_AI_EXECUTION_RULES.md` §4 禁改清單硬停規則：出現額外受保護範圍時先回報，不順手修改。

1. 原因：提供個人採買分類管理並可靠備份，不增加無必要的封存設定資料。
2. 影響：以下一個未使用 App generation 建立新 shell，基準為現行 v140，預計 v141；新 shell 內的選項、表單、商品驗證與備份流程及必要文件／測試。PWA 同一風險群組的 App version、BUILTIN HTML marker／generated asset、`sw.js`、`runtime-assets.json` 與 `netlify.toml` 對應 header 必須同步；root v110 bridge、既有 published shell 及 frozen SW fixture 保持原 bytes。BUILTIN 只用已核准快照經 generator preview／write／readback，不手改、不抓 live Ledger。不動 CMS／Sheet Schema、Apps Script、團體帳語意、OAuth、封存格式或 main；不在本階段推送。
3. 風險：刪除選項造成商品掉資料、還原丟失分類或記帳關聯、部分寫入，以及 mixed-generation PWA。以真實 store 還原矩陣、商品讀寫／歷史呈現、archive 固定格式與 checksum 回歸、SW 原子換代／離線及三情境 QA 防守。
4. 復原：若發現缺陷，以下一個未使用 generation forward bump 修復並保留 v10 備份及自訂商品分類相容性；不得直接用只接受固定分類的舊程式處理新資料、倒退覆寫 generation 或刪除 Service Worker。不得以刪個人資料作為復原。

## 驗證與完成判準

- 選項 store：預設、空清單、增加、重複／空白／超長拒絕、字串邊界名稱、邊界排序、刪除與重開、寫入失敗保持原狀。
- 商品：自訂選項新增與編輯、刪除後完整讀取及修改其他欄位、清空分類、不重建刪除選項、不丟 allocation／已記帳關聯、不擅自修改同類商品。
- 備份：v1–v10 真實還原矩陣、舊版夾帶欄位忽略、v10 缺／壞欄位拒絕、空清單／排序／孤立歷史分類成功恢復、新 key 注入寫入失敗後全有或全無、未知未來版本拒絕、照片引用剝除維持。
- 封存：含自訂分類的商品可以 round-trip 並唯讀顯示；JSON 不新增分類設定欄位；既有 v1 fixture/checksum 繼續驗證；既有 eight-sheet／photo／Queue 排除及回顧筆記測試仍通過。
- 瀏覽器：設定第四項與返回、手機窄版與鍵盤、分類 chip 順序、刪除已使用選項再編輯、備份還原及 inactive 守門。
- 交付前：完整 Node 與 Playwright 套件、斷網內建／連網同步／旅行日三情境的 healthCheck 和零 pageerror、SW 升級／失敗續命／離線、四項文件／版本／資產 gate 與 diff check。真機驗收另由 Bar 回報，不以桌機測試代勾。
